Child dimensions derived from parent parameters

A reusable child keeps half-size expressions from its parent

Verified scpf Parent 120 × 80 × 10 mm; child 60 × 40 × 6 mm derived from half width/depth

What this verifies

A parent block and child component preserve width and depth expressions so saved-design edits to the parent rebuild both bodies.

scpf source

scpf/model.py
"""Qualification: child dimensions intentionally derived from parent parameters."""


class ParentBlock:
    width = 120.0
    depth = 80.0
    HEIGHT = 10.0

    def build(self):
        return Box(self.width, self.depth, self.HEIGHT, anchor=Anchor.BOTTOM)


class DerivedChild:
    width = 60.0
    depth = 40.0
    HEIGHT = 6.0
    Z_BOTTOM = 20.0

    def build(self):
        return Box(
            self.width,
            self.depth,
            self.HEIGHT,
            anchor=Anchor.BOTTOM,
        ).move(z=self.Z_BOTTOM)


class ParentDerivedChildSize:
    base_width = 120.0
    base_depth = 80.0

    def build(self):
        parent = ParentBlock(
            width=self.base_width,
            depth=self.base_depth,
            name="parent",
        )
        child = DerivedChild(
            width=half(self.base_width),
            depth=half(self.base_depth),
            name="child",
        )

        return parent + child


ParentDerivedChildSize()

Engineering explanation

Child dimensions derived from parent parameters

Documentation provenance: the engineering text below is copied verbatim from the last canonical qualification/cases.py source before its removal, commit be40b09e7454a90e87d83768a9e7453c52ba5d76.

Legacy group: parameters

Saved-design required: true

Goal

Isolate one dependency contract: a reusable child receives width and depth expressions derived from parent parameters, and those child dimensions remain editable/associative in the saved SolidCraft design.

Forge API

DerivedChild(width=self.base_width / 2, depth=self.base_depth / 2)

Forge model

One ParentBlock and one DerivedChild. Only base_width and base_depth are published as document parameters; the child carries expressions that reference those existing parent parameters instead of receiving independent duplicated values.

How Forge builds it in SolidCraft

The parent and child sketch dimensions preserve base_width/base_depth expressions. Forge must not flatten base_width / 2 or base_depth / 2 to numeric constants when compiling the child component.

SolidCraft result

At 120x80 mm parent size, the child measures 60x40 mm. Its fixed height and fixed body layout are deliberately unrelated to this qualification.

Saved-design test

Change base_width/base_depth from 120x80 to 160x120 mm in the saved .sc design; without rerunning Python the child must rebuild from 60x40 to 80x60 mm.

Geometry evidence

Geometry-rationale provenance: copied verbatim from qualification/geometry_contracts.py at commit be40b09e7454a90e87d83768a9e7453c52ba5d76.

Bounds sufficient: true

The geometry is two rectangular bodies whose declared sizes and positions are sufficient; the parent-to-child expression is proved by native mutation.

Reference notes

  • SolidCraft — Native parameters and expressions must preserve the parent-to-child dimensional dependency after the Python compiler has finished.
  • PythonSCAD — The Python model expresses the dependency with ordinary arithmetic rather than a special application-specific sizing API.

cadquery/model.py
"""CadQuery reference with child dimensions derived from parent values."""

import cadquery as cq


base_width = 120.0
base_depth = 80.0

parent = cq.Solid.makeBox(
    base_width,
    base_depth,
    10,
    cq.Vector(-base_width / 2, -base_depth / 2, 0),
)
child = cq.Solid.makeBox(
    base_width / 2,
    base_depth / 2,
    6,
    cq.Vector(-base_width / 4, -base_depth / 4, 20),
)

model = cq.Assembly()
model.add(parent, name="parent")
model.add(child, name="child")

from build123d import Align, Box, BuildPart, Locations

with BuildPart() as model:
    Box(base_width, base_depth, 10, align=bottom)
    with Locations((0, 0, 20)):
        Box(base_width / 2, base_depth / 2, 6, align=bottom)
