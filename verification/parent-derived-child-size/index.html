Child dimensions derived from parent parameters

What this example makes

At 120x80 mm parent size, the child measures 60x40 mm. Its fixed height and fixed body layout are deliberately unrelated to this qualification.

Forge code

This is the complete Forge source used for this example.

"""Qualification: child dimensions intentionally derived from parent parameters."""


class ParentBlock:
    width = 120.0
    depth = 80.0
    HEIGHT = 10.0

    def build(self):
        return Box(self.width, self.depth, self.HEIGHT, anchor=Anchor.BOTTOM)


class DerivedChild:
    width = 60.0
    depth = 40.0
    HEIGHT = 6.0
    Z_BOTTOM = 20.0

    def build(self):
        return Box(
            self.width,
            self.depth,
            self.HEIGHT,
            anchor=Anchor.BOTTOM,
        ).move(z=self.Z_BOTTOM)


class ParentDerivedChildSize:
    base_width = 120.0
    base_depth = 80.0

    def build(self):
        parent = ParentBlock(
            width=self.base_width,
            depth=self.base_depth,
            name="parent",
        )
        child = DerivedChild(
            width=half(self.base_width),
            depth=half(self.base_depth),
            name="child",
        )

        return parent + child


ParentDerivedChildSize()

API used

"""CadQuery reference with child dimensions derived from parent values."""

import cadquery as cq


base_width = 120.0
base_depth = 80.0

parent = cq.Solid.makeBox(
    base_width,
    base_depth,
    10,
    cq.Vector(-base_width / 2, -base_depth / 2, 0),
)
child = cq.Solid.makeBox(
    base_width / 2,
    base_depth / 2,
    6,
    cq.Vector(-base_width / 4, -base_depth / 4, 20),
)

model = cq.Assembly()
model.add(parent, name="parent")
model.add(child, name="child")

from build123d import Align, Box, BuildPart, Locations

with BuildPart() as model:
    Box(base_width, base_depth, 10, align=bottom)

How Forge builds it in SolidCraft

The parent and child sketch dimensions preserve base_width/base_depth expressions. Forge must not flatten base_width / 2 or base_depth / 2 to numeric constants when compiling the child component.

One ParentBlock and one DerivedChild. Only base_width and base_depth are published as document parameters; the child carries expressions that reference those existing parent parameters instead of receiving independent duplicated values.

Reference documentation

  • SolidCraft — Native parameters and expressions must preserve the parent-to-child dimensional dependency after the Python compiler has finished.
  • PythonSCAD — The Python model expresses the dependency with ordinary arithmetic rather than a special application-specific sizing API.
