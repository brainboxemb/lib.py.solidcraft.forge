Configuration Symbolic Math

Native configuration rows drive min, sqrt, round, floor, max and abs expressions

Verified scpf Small size=60; Medium size=70; Large size=100

What this verifies

One box keeps derived dimensions native instead of baking the current Python values. Switching Small, Medium and Large changes one source parameter and SolidCraft recomputes several non-linear and quantized expressions.

scpf/model.py
"""Configuration-driven native symbolic CAD math qualification."""


class ConfigurationSymbolicMath:
    size = 70.0
    limit = 80.0
    offset = 20.0
    grid = 7.5
    pitch = 12.0
    step = 1.0
    wall = 4.0
    bias = -3.0

    def build(self):
        span = cadmath.sqrt(
            cadmath.min(self.size, self.limit) ** 2
            - self.offset ** 2
        )
        grid_span = cadmath.round(self.size / self.grid) * self.grid
        height = (
            cadmath.floor(self.size / self.pitch) * self.step
            + cadmath.max(self.wall, cadmath.abs(self.bias))
        )
        body = Box(
            span,
            grid_span,
            height,
            anchor=Anchor.BOTTOM,
        )
        return Configure(
            body,
            active="Medium",
            columns=(Param(self.size),),
            rows={
                "Small": ("60 mm",),
                "Medium": ("70 mm",),
                "Large": ("100 mm",),
            },
        )


ConfigurationSymbolicMath()

Engineering explanation

This case verifies that configuration rows can drive derived native CAD expressions, not only direct dimensions.

The model has one configured source parameter, size. Its box dimensions are derived from ordinary Forge symbolic values:

  • length: sqrt(min(size, limit)^2 - offset^2);
  • width: round(size / grid) * grid;
  • height: floor(size / pitch) * step + max(wall, abs(bias)).

The active Medium row uses size = 70 mm. The saved SolidCraft design is then reopened and switched to Small and Large. The body envelopes must change to the dimensions recomputed by SolidCraft from those expressions.

Forge never calls pv() for these relationships and never substitutes the current Python result into the feature command. The native feature inputs retain the source parameter names, so configuration changes remain geometry-driving.

Model stages

  1. Keep all source dimensions as native model parameters
  2. Derive length through min plus sqrt and squared symbolic expressions
  3. Derive width through round and grid spacing
  4. Derive height through floor plus max and abs
  5. Reopen the saved design and switch native configuration rows
