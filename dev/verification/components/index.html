Verification

Reuse one component definition in two placements

Two touching occurrences share one reusable Block definition

Verified scpf Block 40 × 30 × 10 mm; second occurrence translated 40 mm in X

What this model makes

One Block component definition is instantiated twice with a simple translated copy and no attachment relationship.

scpf source

Complete primary source from the site branch; built revision below.

scpf/model.py
class Block:
    length = 40.0
    width = 30.0
    height = 10.0

    def build(self):
        return Box(self.length, self.width, self.height, anchor=Anchor.BOTTOM)


class TwoBlocks:
    def build(self):
        left = Block()
        right = left.copy(
            placement=Placement(x=Block.length),
        )

        # Drawing intent belongs to the finished design, not Block's reusable
        # definition. SolidCraft creates the sheet and standard views natively.
        return (left + right).with_drawing(
            left,
            name="Block drawing",
        )

Model stages

  1. Create one reusable Block component
  2. Copy the same definition with a 40 mm X placement
  3. Return both occurrences as one assembly
  4. Add a native A3 technical drawing documenting the left Block component

Engineering explanation

Reuse one component definition in two placements

Documentation provenance: the engineering text below is copied verbatim from the last canonical qualification/cases.py source before its removal, commit be40b09e7454a90e87d83768a9e7453c52ba5d76.

Legacy group: components

Goal

Verify that one reusable component definition can have two occurrences with ordinary Placement and no attachment relationship.

Forge API

left = Block(); right = left.copy(placement=Placement(x=Block.length))

Forge model

Two ModelInstance occurrences share one ModelDefinition. The second occurrence carries only Placement metadata; neither occurrence carries an Attachment.

How Forge builds it in SolidCraft

Forge creates one Block component definition and one occurrence.copy with translate=[40,0,0]. No joint.create and no later occurrence.move are needed.

SolidCraft result

Two identical blocks touch face-to-face at X=20 while retaining one shared editable component definition.

Saved-design test

No mutation in this base case; parameter-driven Placement is qualified separately.

Geometry evidence

Geometry-rationale provenance: copied verbatim from qualification/geometry_contracts.py at commit be40b09e7454a90e87d83768a9e7453c52ba5d76.

Bounds sufficient: true

The two body sizes and positions describe the visible result. The saved SolidCraft model is checked separately to confirm that both occurrences reuse one component definition.

Reference notes

  • SolidCraft — One component definition may be placed more than once; this case qualifies that basic component/occurrence structure without introducing a joint.
