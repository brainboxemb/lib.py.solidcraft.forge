Forge API

Primary cross-object API contract. This document defines stable user-facing Forge/SCPF semantics that span more than one public Python object. Exact exported names, signatures, defaults and enum members come from the current Python implementation and its public docstrings. The generated API reference and agent index are derived from those implementation sources.

When implementation and this cross-object contract disagree, treat that as documentation/API drift to be resolved explicitly; do not silently preserve obsolete wording from this document.

SCPF exposes CAD objects and relationships, not JSON commands, transports, or an independent geometry engine. SolidCraft creates and evaluates the actual geometry.

Modelling style: object-first assemblies, expression-first geometry

Forge is deliberately object-first at the component/assembly level and expression-first inside component geometry.

At assembly level, named Python objects represent meaningful physical occurrences:

left = Board()
right = left.copy(
    placement=Placement(x=160)
)
bracket = CornerBracket().attach(left, ...)

The variables represent parts in the design, so later relationships refer to the actual Python occurrence object rather than a generated SolidCraft label.

Inside one component, geometry remains a lightweight feature/expression model:

class Board:
    def build(self):
        body = Box(self.width, self.depth, self.height)
        holes = Hole(d=5, depth=Depth.THROUGH_ALL).repeat_linear(...)
        return body - holes

Do not turn every primitive or feature into an assembly object. Conversely, do not flatten physical assembly parts into an anonymous transform expression tree. This boundary is intentional and is part of the Forge API design.

User-facing model

A model does not need @dataclass. Numeric class fields are model parameters:

class Enclosure:
    length = 80.0
    width = 50.0
    height = 30.0
    wall = 2.0

A model should express relationships semantically. Do not copy coordinates from one part into another merely to make a render line up.

Placement vocabulary

Forge separates position, surface support, sketch-local placement and assembly attachment. These operations are deliberately not synonyms.

shape-relative alignmentshape.at(target)Align the supported child CENTER to the target CENTER. Explicit anchor forms may extend this contract where documented. It does not select a support face.

Native primitive anchor datum

Direct standard 3D primitives use CENTER as their constructor datum:

box = Box(80, 50, 10)
pin = Cylinder(d=8, h=20)
ball = Sphere(12)

The public signatures are:

Box(length, width, thickness, *, anchor=Anchor.CENTER)
Cylinder(*, d, h, axis=Axis.Z, anchor=Anchor.CENTER)
Cone(*, d, top_d=0, h, axis=Axis.Z, anchor=Anchor.CENTER)
Sphere(radius, *, anchor=Anchor.CENTER)

anchor selects which world-cardinal primitive datum lies at model coordinate (0, 0, 0) before later placement.

For Cylinder the anchor is resolved against its world XYZ bounds after the axis is chosen. Axis.X therefore uses LEFT/RIGHT for the axial ends; Axis.Y uses FRONT/BACK; Axis.Z uses BOTTOM/TOP. The remaining cardinal directions select tangent datums on the transverse circular bounds.

Forge lowers each primitive through the native command that SolidCraft already owns:

  • Box CENTER maps to native center; another Box anchor maps to the matching native corner.
  • Cylinder always maps to native base; Forge derives that base from axis, height, diameter and the selected anchor.
  • Cone maps to native solid.cone with diameter, top_diameter, height, axis and a derived native base. Because a cone/frustum has unequal end radii, Forge supports CENTER and the two axial end anchors only.
  • Sphere maps to native center; Forge derives the center from the selected tangent/center anchor.

The same calculation is used in direct and Boolean CSG paths. Do not add a corrective move merely to preserve an old constructor convention.

Dimension-defined sketch profiles Rectangle2D, Circle2D and RoundedRectangle2D are already centered by default from change 0018. Polygon2D and Text2D keep authored coordinates/insertion points.

Box.taper(from_z=..., inset=...) is anchor-aware: from_z is measured from the actual Box bottom face regardless of the constructor anchor.

This is intentionally a breaking cleanup while Forge remains unstable. Models that require an old base/bottom datum must state it explicitly with anchor=.

See change 0022.

at()

at() is geometric placement/alignment.

pin = Cylinder(d=8, h=20, axis=Axis.X).at(10, 0, 5)
centered = Cylinder(d=8, h=30, axis=Axis.X).at(body)

shape.at(target) means CENTER-to-CENTER for supported direct shapes. It does not mean “put this on a face”. Use on() or Sketch(on=...) for that intent.

on()

on() selects a target surface for a within-component feature.

holes = Hole(d=8, depth=Depth.THROUGH_ALL).repeat_linear(
    count=2,
    spacing=self.width - 24,
    axis=Axis.X,
).on(plate, face=Faces.TOP)

boss = Cylinder(d=24, h=14).on(plate, face=Faces.TOP)

For a Hole, face=Faces.TOP means drilling starts at the current top surface and proceeds inward. Faces is surface-selection vocabulary; it is not an assembly attachment vocabulary.

Explicit Sketch

An explicit Sketch is user-authored 2D design intent. It is not an implementation detail of a 3D primitive.

with Sketch(name="Rounded pad", on=body, parent=Anchor.TOP) as pad:
    pad.add(
        RoundedRectangle2D(40, 30, 5),
        anchor=CENTER,
    )

body = body + pad.extrude(8)

For Sketch(on=target, parent=Anchor.TOP):

  • Forge asks SolidCraft for the current body faces and selects the unique largest planar +Z face;
  • Forge passes SolidCraft’s returned face pick and face index to native sketch.create;
  • SolidCraft owns the persistent face attachment and the sketch’s local coordinate frame;
  • Forge passes authored profile coordinates directly in that native sketch frame instead of adding a reconstructed face-centre offset;
  • project_edges=False is explicit so the result does not depend on a session setting;
  • anchor=None means use the profile type’s defined default;
  • for Circle2D, Rectangle2D and RoundedRectangle2D that default is CENTER;
  • explicit anchor=CENTER centres a dimension-defined profile on the sketch origin;
  • a numeric offset=(u, v) is reserved for a real design displacement.

Therefore code such as offset=(-width/2, -depth/2) used only to emulate centering is a smell. Circle2D, Rectangle2D and RoundedRectangle2D use CENTER when anchor is omitted; offset=(u, v) is applied afterwards as a real local design displacement.

Polygon2D is different because its vertex coordinates already define its sketch-local placement. Text2D likewise uses SolidCraft’s text insertion point. For these coordinate-defined profiles an omitted anchor remains None, so Forge does not invent a profile centre. Text2D may still use Sketch.add(..., offset=(u, v)) to set its native insertion-point displacement. Explicit anchor=CENTER is not supported for Polygon2D or Text2D yet. Polygon2D itself is supported inside normal standalone explicit Sketches and face-attached explicit Sketches; its authored vertex coordinates remain sketch-local in either case.

Semantic profile centering was introduced by change 0018. The profile-specific omitted-anchor rule that preserves coordinate-defined Text2D placement is recorded in change 0020.

Selective Sketch extrusion uses SolidCraft’s own profile selection. Pass fixed sketch-local points with Sketch.extrude(..., profiles=[(x, y), ...]). Forge sends those points as native solid.extrude profiles selections; it does not expose profile indices or generated curve ids. SolidCraft 0.42 stores successful point selections by their surrounding curves where possible, so the selected profile can be found again when the saved design recomputes. exact_regions=True requests the exact region containing each point.

Profile pick points are fixed numeric authoring picks, not editable Forge Parameters. SolidCraft 0.42’s point-selection command field accepts numeric Sketch coordinates rather than parameter expressions.

A direct 3D primitive such as Box remains a native primitive; Forge must not synthesize an unnecessary Sketch merely to construct it.

Connected mixed line/arc profiles

Use a connected profile builder when one closed Sketch region mixes straight segments and true circular arcs:

with Sketch(name="Blank", plane="XY") as blank:
    contour = blank.profile(start=(0, 0))
    contour.line_to((40, 0))
    contour.arc_through_to((40, 20), through=(50, 10))
    contour.line_to((0, 20))
    contour.line_to((0, 0))
    contour.close()

solid = blank.extrude(8)

The same closed profile can start a native sheet-metal body:

sheet = blank.sheet_metal(
    thickness=2,
    bend_radius=2,
)

Available initial segment methods:

contour.line_to(end)
contour.arc_through_to(end, *, through)
contour.arc_center_to(end, *, center, clockwise=False)
contour.close()

All coordinates are sketch-local. Parameter/Expression values remain editable native point expressions. Forge lowers arcs to native SolidCraft arc commands; it never replaces them with short polygon edges.

Each call starts at the previous segment’s endpoint. Author the final segment back to the original start point, then call close(). close() validates closure but does not invent geometry.

Tangent-arc authoring is deliberately not part of this first slice because the native command addresses a previous curve entity. Forge will not expose or guess generated SolidCraft ids merely to add syntactic sugar.

Native Sketch pattern and mirror operations

A profile already authored in the active Sketch can seed an associative native rectangular pattern:

seed = sketch.add(Circle2D(d=20), offset=(-304, 0))
row = sketch.rectangular_pattern(
    seed,
    count=9,
    spacing=76,
    direction=Axis.X,
)
sketch.mirror(row, axis=Axis.Y)

The source may also be a supported Slot profile or a result returned by an earlier supported Sketch pattern/mirror operation. Pattern and mirror return Sketch operation handles; they do not expose SolidCraft curve ids.

Current limits include attached Sketch qualification, rectangular patterns, fixed 2D directions or Axis.X/Axis.Y, and mirror over the Sketch X/Y origin axes. A SolidCraft mirror keeps the entity set selected when the mirror was authored; increasing an upstream pattern count later does not automatically add the new entities to that existing mirror.

See change 0033.

Signed and symmetric Sketch extrusion

The current public signature is:

Sketch.extrude(
    distance,
    *,
    sym=False,
    profiles=None,
    exact_regions=False,
)

A positive finite distance follows the sketch-plane normal. A negative finite distance reverses that normal. sym=True requires a positive finite distance and splits the extrusion equally across both sides of the sketch plane. Depth.THROUGH_ALL is available only for an attached Sketch and cannot be combined with sym=True.

Forge does not expose a second direction= argument for current Sketch extrusion. Direction is expressed by the sign of distance or by sym=True.

A standalone Sketch extrusion is a normal solid Boolean operand:

with Sketch(name="Rear recess", plane="YZ") as recess:
    recess.add(RoundedRectangle2D(70, 202, 20), offset=(85, 263))

cut = recess.extrude(14, sym=True)
body = body - cut

+, - and & lower directly to the same native solid.extrude feature with SolidCraft operations join, cut and intersect respectively. Forge does not create a temporary body/combine sequence, and the standalone Sketch remains authored on its own world/work plane.

A standalone Sketch may also declare an explicit local frame with origin=(x, y, z) and rotation=(rx, ry, rz). Extruding that Sketch and using it as a normal Boolean operand preserves the rotated native Sketch frame, so non-axis-aligned cutters do not need consumer-local transform hacks:

with Sketch(
    name="Tip wedge",
    plane="XY",
    origin=(-12, 0, 0),
    rotation=(90, 0, 45),
) as wedge:
    Polygon2D([(-4, -4), (4, -4), (0, 4)])

body = body - wedge.extrude(8)

See change 0024 and change 0043.

Native Slot profiles

Explicit Sketches support the five native SolidCraft Slot constructors:

SlotCenterToCenter2D(p0, p1, width)
SlotOverall2D(p0, p1, width)
SlotCenterPoint2D(center, end, width)
SlotArcThreePoint2D(start, through, end, width)
SlotArcCenter2D(center, start, width, *, end=None, sweep=None)

All five constructors accept a positive numeric width or an editable Parameter / Expression width.

The three straight constructors also accept parameterized authored endpoints when the current Slot axis is horizontal or vertical. Forge keeps SolidCraft’s native point fields numeric, creates numeric seed geometry, and drives native length, orientation and middle-position dimensions instead. Saved-design parameter changes therefore rebuild the same native Slot history without rerunning Forge Python.

For a parameterized horizontal Slot, both authored Y coordinates must represent the same symbolic intent; the equivalent rule applies to X for a vertical Slot. Parameterized diagonal straight Slots are not supported. Fixed numeric diagonal Slots continue to use the direct native creator. Saved-design position changes may move a parameterized straight Slot on its authored side of the sketch origin; crossing an origin axis is not supported in this release.

The two arc-Slot constructors keep fixed numeric authored points in this release, while their width may be parameterized.

Slots can participate in the supported native sketch rectangular_pattern() and mirror() operations.

See change 0027.

Exploded assembly presentation

Exploded views are persistent SolidCraft presentation state on a completed Assembly. They do not rewrite occurrence Placement or attachment relationships.

assembly = first + second + third
assembly = assembly.with_exploded_view("Service", scale=1.25)
assembly = assembly.with_exploded_view(
    "Instructions",
    moves=[
        (second, (0, 25, 0)),
        (third, (0, 50, 10)),
    ],
)
assembly = assembly.show_assembled()

Automatic mode delegates the explosion to native explode.create(scale=...). Explicit mode stores Forge occurrence identities and resolves them to native replay occurrence ids during assembly lowering. show_exploded(name) selects a stored presentation and show_assembled() emits explode.show(view=None). Define views after composing the final Assembly; adding occurrences afterwards is rejected so automatic view scope cannot change silently.

Native component drawings

A technical drawing is attached to the completed design, not to the reusable component definition.

For a standalone component occurrence:

part = Bracket()
return part.with_drawing(name="Bracket drawing")

For one component inside an Assembly:

left = Block()
right = left.copy(placement=Placement(x=40))
return (left + right).with_drawing(left, name="Block drawing")

with_drawing(...) creates a persistent native SolidCraft drawing using the iso-a4-part template by default. Its first sheet documents the selected native component and SolidCraft creates the standard front, top, right and isometric view layout. Forge restricts those views to the selected occurrence subtree using native drawing-view source settings.

A normal SCPF build also publishes that drawing as a native vector PDF below drawings/. The filename is derived deterministically from the drawing name; for example name="Block drawing" produces drawings/Block-drawing.pdf. Use template="iso-a3-part" when an A3 sheet is more appropriate for a complex part.

The drawing API accepts name=, template= and sheet_name=. Compose the final Assembly before adding drawing intent; adding occurrences afterwards is rejected. Dimensions, balloons, parts lists and other annotations are not part of this first slice.

For a component inside a larger assembly, SolidCraft currently fits the standard view group before Forge narrows the views to that component. The drawing is valid, but its scale may therefore be conservative compared with a standalone component drawing.

Occurrence Placement

Placement is reserved occurrence metadata, separate from component model parameters:

left = Board(
    width=frame_wood_thickness,
)

right = left.copy(
    name="right",
    placement=Placement(
        x=160,
    ),
)

Placement(x=0, y=0, z=0, rotation=None) stores the absolute pose in the parent coordinate frame. Position values may contain Parameters or Expressions.

The component factory consumes placement= before building the reusable component definition, so placement never becomes a model parameter. There is no separate public Position object and no occurrence .at(), .move() or .rotate() for initial placement.

SolidCraft 0.42 can apply a numeric translation directly in occurrence.copy(..., translate=...). Forge uses that direct form whenever it is sufficient.

Some Placements need a second native command. Examples are a rotated copy, a symbolic position, or the first occurrence created by component.create. SolidCraft returns the real occurrence id from component.create and occurrence.copy. Forge therefore gives that returned id a named replay variable such as $board_2.

The replay document stores the variable name, not the temporary SolidCraft id. Every live run and every later replay binds the variable again from the command result before a command uses it. Forge never predicts SolidCraft browser names such as Board:2.

This keeps copy(placement=...) as one Forge operation even when SolidCraft needs more than one native command to realise the pose. The second native occurrence.move is a backend detail; it does not add a second Forge movement operation.

Placement must not create a joint.create as an implementation workaround. Attachments remain explicit relationships and Placement expressions reuse existing parameters instead of publishing helper parameters.

The replay-variable correction is recorded in change 0013.

SolidCraft 0.42 has one grounding limitation: an expression-based occurrence.move on a grounded occurrence does not follow later parameter changes. Therefore Forge leaves a physical root occurrence ungrounded when its Placement position contains Parameters or Expressions. A fixed root occurrence still uses the normal grounded behaviour. This is a backend compatibility rule, not a change to the public meaning of Placement. See change 0014.

attach()

attach() is reserved for explicit relationships between reusable component occurrences in an assembly. It is the public Forge relationship; SolidCraft joint.create is an internal lowering detail.

right = Block().attach(
    left,
    parent=Anchor.RIGHT,
    child=Anchor.LEFT,
)

A local planar offset=(u, v) on an attachment is measured in the attachment frame, not in world XY.

Forge generates replayable SolidCraft 0.42 commands and never makes up occurrence names such as Block:2. Every physical occurrence has a stable Forge-side id and a deterministic replay variable. During live execution or later replay, component.create and occurrence.copy bind those variables to the actual SolidCraft occurrence ids before a joint command uses them.

Copied occurrences can therefore be valid attachment endpoints without predicting browser numbering. The replay document still contains only the variable name; concrete runtime ids remain in the separate replay log.

A normal attachment currently requires both parent and child Placement rotations to be None. Forge does not yet transform every Anchor, AnchorFrame and AnchorTopology point/axis through occurrence rotation, so a rotated parent or child is rejected before command lowering rather than using a translation-only approximation. Ordinary rotated Placement remains supported outside normal attachments. as_built=True also remains compatible with rotated Placement because it relates already-positioned occurrences and does not lower anchor frames.

Chained normal attachments remain unsupported until their SolidCraft solve and replay order has been qualified. See change 0010, change 0013 and change 0017.

group()

group(name) changes only the SolidCraft browser hierarchy.

Forge represents the group with an empty SolidCraft component and explicitly sets that group to grounded=false. Grouping must not add a joint, Placement or solver constraint.

If the physical root occurrence is inside a group, grouping itself does not change its grounding decision. The empty group does not become the fixed part. For SolidCraft 0.42, a root occurrence with parameter-driven Placement remains ungrounded so its occurrence move can follow later parameter changes.

One reusable definition may have occurrences in different groups. Forge uses SolidCraft 0.42 occurrence.copy(parent=...) when a later copy belongs under a different group or back at the design root. The component definition remains shared.

See change 0011.

Direction, face and anchor vocabulary

Cardinal direction names are shared where their geometric meaning is shared: TOP, BOTTOM, LEFT, RIGHT, FRONT, BACK.

  • Faces selects a surface for within-component feature placement.
  • Anchor describes an attachment/alignment reference.
  • Direction selectors may be composed, for example BOTTOM + LEFT.
  • Component anchors may identify a face or a rectangular corner such as FRONT_TOP_RIGHT.
  • AnchorFrame is an oriented local attachment coordinate frame: origin locates the datum, z gives its facing direction and x fixes clocking.
AnchorFrame(
    origin=(10, 25, 0),
    z=RIGHT,
    x=UP,
)

Put an anchor on a reusable component only when the datum is intrinsic to that physical component. If the datum exists only because of one assembly, the assembly owns the AnchorFrame.

Parameter intent

Numeric names are part of the public API contract:

Python nameMeaningNative SolidCraft parameter
WIDTH = 100.0fixed constantno
_pitch = 160.0Forge/build-time inputno
width = 100.0editable model parameteryes

A public model parameter that disappears before native compilation is suspicious. Forge emits ModelParameterWarning instead of silently pretending the design is still associative. Use pv() only where Python genuinely needs a concrete number.

Reusable child-component defaults are fixed unless explicitly published with component(..., include=...). For example:

Bracket = component(
    CornerBracket,
    include=("inside_corner_radius",),
)

include="*" explicitly publishes all public child defaults. A mapping may publish one selected child default under a chosen shared model name.

When several parts must share one parent parameter, pass the parent Parameter or Expression directly:

bottom = BottomBoard(corner_radius=self.corner_radius)
roof = RoofBoard(corner_radius=self.corner_radius)
bracket = Bracket(inside_corner_radius=self.corner_radius)

Forge must preserve that existing dependency instead of creating unrelated or duplicated child parameters. This contract is recorded in change 0003.

Reusable component definition identity also includes fixed build-only inputs. Forge rejects arbitrary mutable/opaque Python objects, but its own immutable selector values are valid build inputs when they reduce to deterministic primitive data. This includes public expressions such as BOTTOM + LEFT, Edges.from_profile(...), axis tokens such as X, and fixed bound offsets such as X.MIN + 10. Two different selector inputs must not share one native component definition. See change 0021.

Parameter namespacing applies only to native CAD expressions. Ordinary strings are opaque user data. A text value, material name, sketch name, feature name or font name must never be rewritten merely because one word matches a parameter name.

For example, publishing a child parameter named width may rename the native parameter reference to d1_Label_width, but Text2D("width") must still produce the literal text "width". This compiler rule is recorded in change 0015.

Parameter publication by itself is not proof that a saved design remains associative. Forge tracks dependencies carried by emitted native expressions. A public parameter with no emitted dependency triggers ModelParameterWarning. If user model code calls pv() on a parameter that also remains native elsewhere, Forge warns that only part of the model may follow later SolidCraft edits. Internal Forge numeric checks and authoring-time pick coordinates do not count as user pv() calls.

Root model classes and root @assembly classes use the same diagnostic rule. See change 0016.

Features and operations

  • + joins/adds the described CAD feature to the model; Hole intent lowers to a cut.
  • - expresses subtraction/cut where supported.
  • & expresses intersection where supported.
  • shell(), fillet() and chamfer() are modifiers of supported feature trees.
  • rectangular_pattern() and circular_pattern() repeat already-applied native history features. Both keep one native SolidCraft pattern feature instead of expanding independent Python copies. Circular patterns support principal or fixed XYZ axes plus an optional fixed axis origin; native construction/edge/face axis selectors are separate future extensions.
  • fillet(..., edges=...) and chamfer(..., edges=...) use the same edge-selection vocabulary where SolidCraft accepts the same edge picks: Edges.VERTICAL, supported two-direction Box edge selectors, Edges.from_profile(...), Edges.from_vertices(...) and explicit XYZ edge picks.
  • Lip, SnapFit, Boss and Rest are object-level feature intents; the compiler chooses the appropriate native SolidCraft representation.
  • Anchor.INNER_BOTTOM refers to the inner floor of a shelled body.
  • X.MIN/CENTER/MAX and Y.MIN/CENTER/MAX express placement relative to parent bounds rather than copied world coordinates.

Native Hole family

Forge exposes explicit native hole intent rather than requiring a caller to construct every recess or thread from Boolean primitives:

Hole(*, d, depth=Depth.THROUGH_ALL, direction=None)

CounterboreHole(
    *,
    d,
    counterbore_d,
    counterbore_depth,
    depth=Depth.THROUGH_ALL,
    direction=None,
)

CountersinkHole(
    *,
    d,
    countersink_d,
    countersink_angle=90,
    depth=Depth.THROUGH_ALL,
    direction=None,
)

ThreadedHole(
    *,
    thread,
    depth=Depth.THROUGH_ALL,
    d=None,
    direction=None,
    hand="right",
    thread_depth=None,
    modeled=False,
    ease_out=None,
)

The simple Hole remains compatible with the existing face-relative repeated hole path. The explicit native Hole-family constructors are positioned with at() and keep their recess/thread intent in one native feature.

Native history patterns

rectangular_pattern() and circular_pattern() operate on already-applied native history features rather than expanding independent Python copies. The source argument is the Forge Shape that was applied to the body; callers do not pass SolidCraft timeline-name strings. Forge resolves that exact source to its native history identity. This includes direct native Hole-family features (Hole1, Hole2, …), native primitive features and the existing named Sketch.extrude() path.

For example:

bolt_hole = Hole(d=8, direction=(0, 0, -1)).at(30, 0, 6)
plate = plate + bolt_hole
plate = plate.circular_pattern(bolt_hole, count=6, axis=Axis.Z)

The source feature is emitted once and the pattern remains one native history feature. Circular patterns support the currently documented principal/fixed XYZ axis and optional fixed axis origin forms. A Shape that is not an already- applied single native history feature is rejected rather than being expanded in Python.

See change 0036.

Reference implementations

Qualification pages compare Forge with PythonSCAD, pyBOSL2 and CadQuery by default. Those references answer “how is the same modelling intent expressed elsewhere?” They are not allowed to redefine Forge behaviour.

PythonSCAD is useful as a neutral Python CSG comparison; pyBOSL2 is especially useful for anchor/attachment vocabulary; CadQuery provides a distinct object/workplane/assembly/Location comparison. If a technically meaningful reference cannot be implemented, the case must carry an explicit documented exception. A missing reference or a convenience-only exception is not qualified evidence.

Responsibility boundaries 

Python objects (SCPF)
  -> semantic compiler
  -> SolidCraft commands
  -> SolidCraft BRep, parameters and editable feature history

Forge may perform small dimension arithmetic needed to describe design intent. It must not implement a competing CAD kernel, transform solver or mating engine.

Never silently treat numeric coordinates as robust long-lived face references. Native save/reopen and parameter-edit tests determine which relationships are truly associative.

Qualification rule

A public API behaviour is not considered complete merely because one example renders correctly. It needs the appropriate Q1-Q6 evidence. A qualification fixture is evidence for this document; the fixture itself is never the API definition.

Sheet metal

Forge sheet metal is native editable SolidCraft history, not a solid-envelope approximation. A sheet body has one active rule that owns material thickness, k_factor and the default bend_radius.

There are two body-creation paths:

  • Sketch.sheet_metal(...) creates a flat sheet from one closed Sketch and defines the sheet rule directly;
  • Shape.contour_flange(...) creates a sheet from a finished connected open Sketch chain and defines the rule for that new body.

Operations on an existing sheet — fold(), flange(), hem(), path_flange() and perforate() — preserve the active sheet history instead of repeating thickness/K-factor/default-radius fields. A feature may still own its own editable dimensions, such as flange height, hem length/gap, an explicit path-flange radius override, or perforation diameter/pitch/margin.

Use Parameters/Expressions for dimensions where the method contract permits them. Current edge picks and straight fold-line coordinates are deliberately fixed finite coordinates. Forge does not turn a numeric pick into a claimed long-lived topology reference.

Native flat-pattern, saved-design and sheet-rule evidence is part of the behavioural contract. A matching formed bounding box alone is not sufficient qualification for sheet-metal history.

Flat sheet and fold

Create a new flat body from a closed Sketch:

with Sketch(name="Blank", plane="XY") as sketch:
    Rectangle2D(80, 40)

sheet = sketch.sheet_metal(
    thickness=2,
    bend_radius=2,
    k_factor=0.5,
    rule_name="Panel sheet",
)

Then bend existing material without restating the rule:

sheet = sheet.fold(
    line=((20, -20, 0), (20, 20, 0)),
    angle=90,
    fixed=(-30, 0, 0),
)

The initial fold() contract accepts one straight line made from fixed XY/XYZ points. angle may be parameterized. Bend allowance and material dimensions remain owned by the active sheet rule.

Sheet edge flange

Add a native flange to one or more selected edges of an existing sheet body:

sheet = sheet.flange(
    edges=[(40, -20, 2)],
    height=20,
    angle=90,
)

Optional native placement controls are available without changing SolidCraft’s default when omitted:

sheet = sheet.flange(
    edges=[(40, -20, 2)],
    height=height,
    angle=bend_angle,
    height_from="inner",
    position="material_outside",
    flip=True,
)

edges currently accepts a non-empty sequence of fixed finite XYZ points only. height may be parameterized and must stay positive. angle may be parameterized and must be non-zero with magnitude below 180°. height_from accepts outer, inner or tangent; position accepts inside, outside, middle, material_outside or tangent. Leave either as None to use SolidCraft’s native default.

The sheet’s existing rule continues to own thickness, K-factor and bend radius. flange() does not expose per-edge segmentation, corner-relief overrides, chained bends or raw SolidCraft dictionaries in this initial API.

Open connected Sketch chains

Use an open chain when downstream native behavior needs a connected Sketch path rather than a closed profile:

with Sketch(name="Contour", plane="XY") as sketch:
    chain = sketch.chain(start=(0, 0))
    chain.line_to((40, 0))
    chain.tangent_arc_to((50, 10))
    chain.line_to((50, 30))
    contour = chain.finish()

Initial builder methods:

chain.line_to(end)
chain.tangent_arc_to(end)
chain.finish()

finish() returns a reusable open-chain Shape. It does not close the chain and does not make it a selectable closed profile.

The initial form requires a standalone Sketch on XY/XZ/YZ. A plane offset= is supported; attached on= and explicit 3D origin= chains are not part of this slice.

The initial tangent-arc form must immediately follow a line segment. Forge uses a private deterministic native line id to satisfy SolidCraft’s tangent reference; callers never pass or receive native curve ids. A line may follow the tangent arc, so normal line/tangent/line contour paths are supported.

Coordinates are sketch-local. line_to() endpoints may use Forge Parameter/Expression values. The initial tangent_arc_to() endpoint must be a fixed finite numeric point because SolidCraft 0.45 rejects expressions in sketch.arc.tangent.end; Forge reports that at authoring time instead of emitting an invalid replay command. Arc-to-arc tangent continuation is not part of this first API slice.

Sheet contour flange

Turn a finished reusable open Sketch chain into a native contour-flange sheet:

with Sketch(name="Contour", plane="XZ") as sketch:
    chain = sketch.chain(start=(0, 0))
    chain.line_to((35, 0))
    chain.tangent_arc_to((40, 5))
    chain.line_to((40, 30))
    contour = chain.finish()

sheet = contour.contour_flange(
    distance=50,
    thickness=2.5,
    bend_radius=2.5,
    k_factor=0.44,
)

Optional controls:

sheet = contour.contour_flange(
    distance=width,
    thickness=2.5,
    bend_radius=2.5,
    k_factor=0.44,
    rule_name="Bracket sheet",
    flip=True,
    reverse=True,
)

distance may be a Forge Parameter/Expression and must stay positive. thickness, bend_radius, k_factor and rule_name define the native sheet rule used for the new body, using the same semantics as Sketch.sheet_metal(). They are not duplicated into the native contour-flange feature.

The receiver must be the Shape returned by chain.finish(). Forge compiles its full ordered line/tangent-arc chain, captures any SolidCraft-generated curve ids through replay bindings and supplies that exact list to sheet.flange(type="contour"). Native curve ids are not part of the public API.

flip and reverse default to false and are emitted only when true. Contour flange creates its own sheet body; use Shape.flange(edges=...) for an edge flange on sheet material that already exists.

Sheet hem

Fold one or more existing sheet edges back while keeping native sheet history:

sheet = sheet.hem(
    edges=[(40, 0, 2)],
    length=12,
    gap=4,
)

edges is currently a non-empty sequence of fixed finite XYZ picks. length must be positive and may remain parameterized. gap is optional; when omitted SolidCraft uses the sheet-rule behaviour. flip=True reverses the hem side. Thickness, K-factor and default bend radius remain inherited from the existing sheet body.

Sheet path flange

Use a finished connected open Sketch chain as the path for a flange on an existing sheet edge:

with Sketch(name="Path", plane="XZ") as sketch:
    chain = sketch.chain(start=(0, 0))
    chain.line_to((0, 14))
    path = chain.finish()

sheet = sheet.path_flange(
    edge=(40, 0, 2),
    path=path,
    radius=3,
)

The current SolidCraft 0.45 contract accepts a fixed XYZ edge pick and a non-empty line-only open chain. Tangent arcs and generic edge selectors are not yet qualified for path flange. radius is optional; omitting it inherits the active sheet rule, while supplying it overrides only this feature’s bend radius. Thickness and K-factor always remain owned by the existing sheet rule.

Whole-sheet perforation

Apply a native manufacturing perforation field to existing sheet material:

sheet = sheet.perforate(
    diameter=5,
    pitch=10,
    margin=5,
    pattern="square",
)

diameter and pitch are positive millimetre values and may remain Forge Parameters/Expressions. margin is optional and positive when supplied; None omits the native field so SolidCraft keeps its documented default equal to the perforation diameter. pattern accepts "staggered" or "square"; the default staggered value is omitted from the native command.

This first API slice applies to the whole sheet only. Forge does not expose the native Sketch/profile-bounded perforation region yet. Perforations remain SolidCraft manufacturing, flat-pattern, DXF and measurement semantics: Forge does not translate them into repeated Hole features or Boolean B-rep cuts.
