# Generated output and Pages

Status: **migration in progress**

Issue #366 tracks the remaining Forge build and Pages publication cut-over to
`tool.cad.ci`.

## Current development source of truth

Current development status comes from:

- editable source on `main` or a PR branch;
- `cad-ci.yml` and local `ci.yml` definitions;
- the output of the current CAD-CI run.

The existing `build` and `gh-pages` branches were generated by the previous
publication architecture and may lag behind current source.

## Intended persistent branch roles

| Branch | Purpose | Human edited |
| --- | --- | --- |
| `main` | source, tests and documentation | yes |
| `build` | durable technical output | no |
| `gh-pages` | browseable website | no |

Generic branch storage, sparse update and publication behaviour belongs to
`tool.cad.ci`.

Forge owns Forge-specific content such as API documentation, example metadata,
site presentation and interpretation of model verification results.

## Item-oriented output

Technical output follows the CAD-CI item that produced it, for example:

```text
scpf/
examples/simple-box/
examples/anchored-holes/
```

The current architecture does not use a second Forge-specific qualification
tree as an execution layer.

## Existing site source

The `site/` directory still contains source from the earlier Forge website.
Parts of it reference the removed qualification package and therefore are not
the current runnable publication pipeline.

That site source is reconciled as part of issue #366, together with the new
durable item output and Pages inputs.

## Historical generated terminology

Older branches and documents may contain names such as `qualification`,
`qualified-output`, or numbered verification levels. Those names describe the
earlier publication/verification architecture.
