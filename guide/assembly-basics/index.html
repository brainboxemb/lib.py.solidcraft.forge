From one component to an assembly

When to use a Shape, component, occurrence, anchor, relationship or group.

Start with the mental model

Forge separates geometry from physical parts and from relationships between parts. Most assembly code becomes much easier once those three levels are kept separate.

1. A component means one physical part

A component is not limited to one primitive. It is the definition of one physical manufactured item. Its build() may contain several primitives, sketches, holes, bosses, fillets and other features as long as they together describe that one part.

from scpf import Box, Cylinder, component

@component
class MountingPlate:
    width = 80.0
    depth = 50.0
    thickness = 5.0

    def build(self):
        plate = Box(self.width, self.depth, self.thickness)
        boss = Cylinder(d=16, h=12).at(0, 0, self.thickness)
        return plate + boss

The plate and cylindrical boss are geometry/features inside one component. They do not need an assembly joint because they are not separate physical parts.

Physical-part test: if the boss is machined, printed or moulded as part of the plate, keep it inside one component. If it is actually a separate brass insert pressed into the plate, make a second component and relate the two occurrences in an assembly.

MountingPlate is the reusable definition. Calling MountingPlate() creates one occurrence; copy() creates another occurrence of the same definition without duplicating the feature history.

2. Put components in one assembly

first = Block(placement=Placement(x=-30))
second = first.copy(placement=Placement(x=30))

assembly = first + second

Here first + second means “these two component occurrences belong to one assembly”. It does not Boolean-union their solids.

Same operator, different level: Shape + Shape describes supported geometric union; occurrence + occurrence builds an assembly of physical parts.

placement=Placement(...) declares the pose when an occurrence is created or copied. It does not create a mechanical relationship; use attach() when another occurrence owns the relationship.

3. Use @assembly when the composition itself is reusable

You do not need @assembly merely because a script contains several components. Use it when the composition itself is a reusable model object that you want to import or instantiate as a subassembly.

from scpf import Anchor, assembly

@assembly
class BlockPair:
    def build(self):
        left = Block()
        right = Block().attach(
            left,
            parent=Anchor.RIGHT,
            child=Anchor.LEFT,
        )
        return left + right

pair = BlockPair()

The component definitions remain the physical parts. BlockPair describes how those occurrences are composed. This is different from group(): an assembly expresses the model composition; grouping controls the native nested hierarchy/browser unit.

4. Use attach() when the relationship is the intent

If the real rule is “the left side of this part belongs on the right side of that part”, encode that relationship instead of calculating a replacement XYZ coordinate yourself.

from scpf import Anchor

left = Block()
right = Block().attach(
    left,
    parent=Anchor.RIGHT,
    child=Anchor.LEFT,
)

assembly = left + right

Forge records an associative attachment between the two occurrences and lowers that to the native SolidCraft relationship mechanism. The anchors say which references are related; they are not just prettier names for a hard-coded XYZ point.

This is the important rule: use an anchor when you need to describe a relationship or semantic mounting reference. Do not add anchors to every component pre-emptively.

5. Which kind of anchor?

Normal rectangular face/corner is enoughAnchor.LEFT, Anchor.FRONT_TOP_RIGHT, etc.

The reference must follow a particular native edge/corner topologyAnchorTopology

Start with the simplest standard Anchor. Move to AnchorFrame or AnchorTopology only when a face/corner reference cannot express the actual mounting intent.

6. Let SolidCraft own the native relationship

Forge describes the relationship; SolidCraft owns the resulting native geometry, occurrence hierarchy and joint data. Forge is not intended to grow a second general mating solver. That is also why a meaningful attach() is preferable to Forge inventing increasingly clever coordinate corrections.

offset=(u, v) moves within the attachment plane, gap is normal distance between references, and angle is the relative turn around the attachment normal. These are relationship values, not a replacement global XYZ transform.

There are two useful attachment modes. Normal attach() uses the chosen references to determine the relationship and placement. Use attach(..., as_built=True) when both occurrences are already in the intended pose and SolidCraft should record that existing pose as a fixed assembly relationship instead of repositioning them.

7. A group is organisation, not a relationship

frame = (left + right).group("Frame")

group("Frame") creates a real nested native component so the occurrences appear together in the SolidCraft browser hierarchy. Grouping does not mate, align or rotate the parts and does not replace attach().

Use a group when the collection itself is a useful named subassembly or browser unit. Do not create a group merely because two components touch.

A practical decision sequence

  1. Will these features be manufactured as one physical item? Keep them in one component, even if the geometry is complex.
  2. Is something installed or manufactured separately? Give it its own component occurrence.
  3. Do you only need a deliberate occurrence pose? Supply placement=Placement(...) when creating or copying it.
  4. Should one separate part follow another semantically? Use attach() and the simplest suitable anchor.
  5. Is a standard face/corner insufficient? Define an AnchorFrame or topology-backed reference at the level that owns that meaning.
  6. Do several occurrences form a useful named subassembly/browser unit? Then use group().

API on this page

These values and signatures are generated from the current Python API. They are shown here so the normal guide flow does not require opening the reference for every detail.

Anchor

Select component attachment references and cardinal directions.

Anchor.CENTER · Anchor.TOP · Anchor.BOTTOM · Anchor.LEFT · Anchor.RIGHT · Anchor.FRONT · Anchor.BACK · Anchor.FRONT_TOP_LEFT · Anchor.FRONT_TOP_RIGHT · Anchor.FRONT_BOTTOM_LEFT · Anchor.FRONT_BOTTOM_RIGHT · Anchor.BACK_TOP_LEFT · Anchor.BACK_TOP_RIGHT · Anchor.BACK_BOTTOM_LEFT · Anchor.BACK_BOTTOM_RIGHT · Anchor.INNER_BOTTOM · Anchor.UP · Anchor.DOWN

Use when: Use cardinal or corner anchors to attach reusable component occurrences, or combine cardinal values to identify Box edges/corners.

Current limits: Anchor is the assembly/alignment vocabulary. Within-component feature placement normally uses Faces instead. INNER_BOTTOM has no direction vector and therefore cannot be used as a cardinal selector.

component() / @component

Declare one reusable physical component definition.

component(cls=None, *, include=())

Use when: Decorate a model class whose build() result represents one reusable physical part. Child defaults stay fixed unless explicitly published with include=. Parent Parameter/Expression inputs remain symbolic.

Current limits: build() must produce one Shape when reused as a component.

assembly() / @assembly

Declare a reusable class that composes component occurrences.

assembly(cls)

Use when: Decorate a class when the class itself represents a reusable assembly or subassembly built from component occurrences and their relationships.

Current limits: build() must return a component occurrence or Assembly. The decorator does not itself create grouping or attachment relationships; those come from the objects returned by build().

Occurrence.copy()

Create another occurrence of the same reusable definition.

Occurrence.copy(self, *, name=None, placement=None)

Use when: Reuse one component definition for another physical occurrence.

Current limits: Attachment state is occurrence-specific and is not copied.

Occurrence.attach()

Create a rigid or planar relationship from this occurrence to another component.

Occurrence.attach(self, target, *, parent=<Anchor.RIGHT: 'right'>, child=<Anchor.LEFT: 'left'>, offset=(0, 0), gap=0, angle=None, as_built=False)

Use when: Placement should be expressed semantically between component references, such as left face to right face or one mounting frame to another, rather than as a calculated global XYZ position.

Current limits: The target must be another component occurrence. Supported standard anchors currently focus on rectangular component geometry; custom AnchorFrame/AnchorTopology references cover more specific datums. as_built=True requires all other relationship arguments to remain at their defaults.

Occurrence.group()

Place this occurrence in a named native subassembly component.

Occurrence.group(self, name)

Use when: Give one occurrence a useful native browser/subassembly parent.

Current limits: Grouping changes hierarchy only. It does not align, attach or otherwise create a mechanical relationship. One occurrence cannot belong to several different groups.

Assembly.group()

Wrap these assembly occurrences in a real nested native component.

Assembly.group(self, name)

Use when: The collection should appear as one named subassembly/browser unit in SolidCraft.

Current limits: Grouping changes native hierarchy, not placement or relationships. Use attach() for mechanical relationships between occurrences.

Custom attachment references

Use richer local or topology-backed datums when a standard Anchor is not enough.

AnchorFrame

AnchorFrame(origin: tuple[float, float, float] = (0.0, 0.0, 0.0), z: tuple[float, float, float] | scpf.core.Anchor = <Anchor.TOP: 'top'>, x: tuple[float, float, float] | scpf.core.Anchor = <Anchor.RIGHT: 'right'>) -> None

Describe one local attachment point and orientation.

Use when: A standard face or corner Anchor is not enough and the mounting datum needs its own local origin plus orientation. A reusable component may expose named AnchorFrame values from anchors(), or an assembly may pass one directly to attach().

Current limits: z and x must be non-zero and must not be parallel. Direct frames on explicitly rotated occurrences have limited support as documented by the assembly guide.

AnchorTopology

AnchorTopology(edge: tuple[float, float, float], on: tuple[float, float, float], corner: tuple[float, float, float] | None = None, z: tuple[float, float, float] | None = None, x: tuple[float, float, float] | None = None) -> None

Describe an attachment datum that follows native SolidCraft topology.

Use when: A relationship should follow a particular edge, adjacent planar face and optionally one endpoint as dimensions change, rather than freezing one XYZ coordinate.

Current limits: edge and on are native selection pick points. Current Forge support focuses on planar-face edges and non-rotated occurrences. z and x, when both supplied, must not be parallel.
