Examples

Configuration Position

One saved native table moves a front-plate occurrence through Front, Below and Service states

Verified scpf Front y=8 z=0; Below y=0 z=-55; Service y=25 z=0

What this model makes

This case proves that one complete assembly can keep a fixed screen while a separate front-plate occurrence follows two native Placement parameters. Reopening the saved design and activating Front, Below or Service moves only that occurrence without rebuilding the Python assembly.

scpf/model.py
"""Generic configuration-table qualification for parameter-driven assembly positions."""


class Screen:
    def build(self):
        return Box(80, 10, 50)


class FrontPlate:
    def build(self):
        return Box(80, 2, 50)


class ConfigurationPosition:
    plate_y = 8.0
    plate_z = 0.0

    def build(self):
        screen = Screen(name="screen")
        front_plate = FrontPlate(
            name="front_plate",
            placement=Placement(y=self.plate_y, z=self.plate_z),
        )
        model = screen + front_plate
        model.configure(
            active="Front",
            columns=(self.plate_y, self.plate_z),
            rows={
                "Front": ("8 mm", "0 mm"),
                "Below": ("0 mm", "-55 mm"),
                "Service": ("25 mm", "0 mm"),
            },
        )
        return model


ConfigurationPosition()

Engineering explanation

This case verifies that one saved native SolidCraft configuration table can move an occurrence inside a complete assembly through ordinary associative placement parameters.

The assembly has two occurrences:

  • screen stays fixed at the origin in every configuration;
  • front_plate is the only occurrence that moves.

The configuration table owns two parameter columns, plate_y and plate_z, which are also the Y/Z values of the front plate’s Placement.

Configurationplate_yplate_zExpected physical state
Front8 mm0 mmFront plate sits directly in front of the fixed screen.
Below0 mm-55 mmFront plate moves below the screen.
Service25 mm0 mmFront plate moves +25 mm on Y while the screen remains fixed.

The verification first saves the design with Front active. It then reopens that saved .sc and activates Below and Service natively. For each state it checks both the SolidCraft parameter values and the measured body envelopes.

The important contract is that switching rows happens in the saved SolidCraft document. Forge does not rebuild the Python assembly to create the alternate positions.

This case does not test feature suppression, camera/render state or alternate assembly topology; those are separate configuration/presentation concerns.
